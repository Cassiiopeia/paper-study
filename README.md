# paper-study

논문을 **끝까지 읽게 만들기 위한** 저장소.
요약을 받아 읽는 것이 아니라, **답을 해야 다음이 열리는** 방식으로 읽는다.

논문 한 편당 세션 하나. 대화하면서 남긴 것이 `notes/` 와 `knowledge/` 에 쌓이고,
다음 세션은 그 기록에서 이어진다.

## 규칙 넷

1. **요약 금지** — 조수는 논문 내용을 먼저 말하지 않는다. "몇 쪽 어느 문단" 까지만 알려준다
2. **통행세** — 직전 구간에 답해야 다음이 열린다. "모르겠다" 는 답으로 치지 않는다
3. **15~20분치씩** — 한 세션에 한 장(章) 이하. 통으로 던지면 안 읽는다
4. **본인 말로 3문장** — 용어 없이 설명 못 하면 그 구간은 안 읽힌 것

전체 규칙은 [CLAUDE.md](CLAUDE.md) 에 있다. 조수가 세션마다 읽는다.

## 읽는 축 — 교수님이 찌르는 여섯 자리

왜 이 문제인가 · 기존과 뭐가 다른가 · 핵심 주장 한 문장 ·
근거가 주장을 받치나 · **한계와 안 되는 경우** · 내 프로젝트에 어떻게 쓰나

## 원문 다루기

이 저장소는 공개되어 있어 원문 PDF 를 평문으로 두지 않는다.
`papers/*.pdf` 는 gitignore 되고 **AES-256-GCM 으로 봉한 `.enc` 만** 올라간다.

```bash
python scripts/vault.py keygen     # 최초 1회. .key 를 만든다
python scripts/vault.py unseal     # .enc -> 평문 PDF (읽기 전)
python scripts/vault.py seal       # 평문 PDF -> .enc (커밋 전)
python scripts/vault.py status     # 무엇이 봉해졌고 무엇이 열려 있나
```

키는 환경변수 `PAPER_STUDY_KEY`(base64 32바이트), 없으면 `.key` 파일에서 읽는다.
**둘 다 gitignore 대상이고, 키 값을 파일·커밋 메시지·대화 어디에도 적지 않는다.**
`keygen` 은 키를 화면에 찍지 않는다 — 터미널 기록에 남기지 않기 위해서다.

nonce 를 원문에서 결정론적으로 뽑으므로 같은 PDF 는 다시 봉해도 암호문이 같다.
불필요한 diff 가 생기지 않는다.

> base64 는 암호화가 아니다. 키 없이 되돌아가므로 원문을 그냥 올린 것과 같다.
> 저작권도 base64 로는 해결되지 않는다 — 걱정된다면 `papers/` 를 통째로 gitignore 하는 편이 깨끗하다.
