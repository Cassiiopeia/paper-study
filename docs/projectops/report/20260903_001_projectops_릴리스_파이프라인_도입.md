# projectops 릴리스 파이프라인 도입

## 개요

논문 튜터 저장소에 이슈·릴리스·버전 관리 체계가 없어, 레포 자체를 고치는 작업이 이슈 없이 곧바로 커밋되고 있었다. project-auto-wizard 를 basic 타입으로 설치해 GitHub 네이티브 릴리스 자동화 워크플로우를 넣고, 개발 브랜치 develop → 릴리스 브랜치 main 구조로 잡았다. 배포 대상 서버가 없으므로 서버 배포·Nexus publish·Secret 백업 워크플로우는 제외했다. 앞으로 레포 개선은 "이슈 생성 → 구현 → 커밋 → 배포" 순서를 따르고, 논문 읽기 세션 기록은 기존대로 바로 커밋한다.

## 변경 사항

### 워크플로우
- `.github/workflows/PROJECT-COMMON-AI-PR-SUMMARY.yaml`: PR 요약 자동화
- `.github/workflows/PROJECT-COMMON-AUTO-CHANGELOG-CONTROL.yaml`: develop→main 릴리스 PR 의 체인지로그 관리
- `.github/workflows/PROJECT-COMMON-ISSUE-HELPER.yaml`: 이슈 제목 정규화·브랜치명 안내
- `.github/workflows/PROJECT-COMMON-README-VERSION-UPDATE.yaml`: README 버전 섹션 동기화
- `.github/workflows/PROJECT-COMMON-RELEASE-PUBLISH.yaml`: 릴리스 생성
- `.github/workflows/PROJECT-COMMON-VERSION-CONTROL.yaml`: 커밋 타입 기반 semver 승격

### 헬퍼 스크립트
- `.github/scripts/version_manager.py`, `changelog_manager.py`, `truncate_release_notes.py`, `issue_helper.py`: 위 워크플로우가 호출하는 스크립트
- `.github/.wizard/baseline.json`: 설치 기준선 (드리프트 감지용). 실행 로그는 gitignore

### 버전·문서
- `version.yml`: 초기 버전 0.0.1, 타입 basic, 브랜치 develop/main
- `README.md`: 버전 섹션 추가 (워크플로우가 갱신)

### 브랜치
- `develop` 브랜치 신설. 이후 모든 레포 개선 작업은 여기서 진행하고 main 은 릴리스 PR 로만 갱신

## 주요 구현 내용

설치 옵션은 `--type basic --main-branch main --develop-branch develop --no-nexus --no-secret-backup` 이다. dry-run 으로 신규 파일 6개·기존 파일 변경 0개를 먼저 확인한 뒤 실제 설치했다. 버전은 자동 감지 대상이 없어 기본값 0.0.1 로 시작한다.

## 주의사항

- 저장소에 `작업전` · `작업중` · `작업완료` 라벨이 없다. 이슈 생성 시 라벨이 조용히 빠지므로 GitHub 레포 설정에서 세 라벨을 만들어 두어야 이후 파이프라인의 라벨 상태 전이가 동작한다.
- Settings → Actions → Workflow permissions 를 Read and write 로 두어야 릴리스·README 갱신 워크플로우가 커밋할 수 있다.
- `WORKFLOW_PAT` 시크릿은 선택이다. 없으면 GITHUB_TOKEN 으로 폴백해 automerge 가 조금 느려질 뿐 동작한다.
- develop 에 커밋만 쌓이고 main 으로 올리지 않으면 버전은 올라가지 않는다. 릴리스는 `/pro-changelog-deploy` 로 develop→main PR 을 만들어 진행한다.
