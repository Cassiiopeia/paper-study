# 논문 튜터 재설계 — "같이 읽기" 설계

이슈: https://github.com/Cassiiopeia/paper-study/issues/2
날짜: 2026-09-03

## 1. 왜 다시 짜나

현재 `CLAUDE.md` 는 "읽어도 안 남는다" 를 막는 데 맞춰져 있다 (카드 · 복습 · 내 말로 설명).
그런데 "안 읽는다" 를 막는 쪽은 거꾸로 간다 — 요약 금지 + 통행세 + 질문 먼저 = "혼자 읽어 와, 채점만 한다".
읽기 전에 시험지부터 받는 구조라 읽을 동기가 죽는다. 실제 첫 세션에서 사용자가 그렇게 말했다.

사용자가 원하는 것:

- 조수가 **키워드와 힌트로 길을 내주고**, 읽는 것은 사용자가 한다 (남는 게 있어야 하니까)
- 읽은 뒤 **핵심을 찌르는 질문** — "왜 이 결론?", "키워드 몇 개 뽑아봐", "조립해봐"
- 틀리면 **조수가 직접 고쳐주고, 사용자가 다시 쓴다** — 맞을 때까지
- **중간중간 되묻는** 반복 학습
- 마지막엔 **남에게 설명할 수 있는 경지**
- 어떤 가르침이 먹혔는지 기록해 **다음 세션이 더 나아지게**

## 2. 원칙 — 무엇이 바뀌고 무엇이 남나

| 지금 | 바꿈 |
|---|---|
| 요약 금지. 쪽 번호만 준다 | **먼저 다 풀어주지 않는다.** 덩어리마다 키워드 3~5개 + 힌트 한 줄까지. 본문 요약은 사용자가 |
| 틀리면 쪽만 짚고 되돌려 보냄 | **직접 고쳐준다** → 사용자가 다시 쓴다 → ○ 까지 반복 |
| 빈 답은 되돌려 보냄 | **힌트 단계 상승** — 키워드 → 문장 위치 → 문장 앞 절반 → 같이 읽기. 막혀서 멈추는 일 없음 |
| 한 세션 한 장(章) | 유지 + **한 번에 한 덩어리** (문단 ~ 소절) |
| 조수는 채점만 | **길잡이 + 채점 + 자기 교정** (플레이북) |

**유지** — 사용자 부담 0 · 1차(뼈대) → 2차(논증) → 3차(비판) → 설명 시험 순서 · 카드와 복습 간격 ·
답 원문 그대로 기록 · 세션 끝 커밋 · 원문은 봉해서만 올린다.

## 3. 덩어리 루프 — 매 문단이 도는 순서

덩어리 = 문단 하나 ~ 소절 하나. 조수가 밀도를 보고 정하고 매번 "N쪽 O문단" 으로 명시한다.
사용자가 "더 잘게" / "더 크게" 라고 하면 조정한다.

```
1. 조수  : "이번 덩어리 — N쪽 O문단" + 키워드 3~5개 + 힌트 한 줄
          (힌트는 '무엇을 찾으며 읽을지' 이지 내용 요약이 아니다.
           예: "X와 Y를 비교하는데, 저자가 어느 편인지 보세요")
2. 사용자: 읽고 답한다
3. 조수  : 질문 1~2개 — 아래 다섯 유형에서 돌려가며
4. 조수  : 판정 ○△✗ + 틀린 곳·빠진 조각을 **직접 말한다** + 근거 쪽
5. 사용자: 반영해 **다시 쓴다**
6. 4~5 를 ○ 까지. 최대 3회. 넘으면 「막힌 자리」+ 카드로 남기고 진행
7. 덩어리 2~3개마다 앞 덩어리 하나를 되묻는다 (세션 안 미니 복습)
8. 장(章) 끝: 본인 말로 3문장 → 04-explain.md 「장별 내 말 요약」에 조립
```

### 질문 다섯 유형

| 유형 | 예 | 노리는 것 |
|---|---|---|
| 요약형 | "이 문단 두 문장으로" | 읽었나 |
| 키워드형 | "강조할 단어 3개, 각각 왜 중요한지" | 무엇이 핵심인지 고르는 눈 |
| 왜형 | "저자가 왜 이 결론으로 갔나 / 왜 이 예시를 골랐나" | 논리 연결 |
| 조립형 | "앞 문단과 이어서 한 줄로" | 흐름 |
| 기법형 | "여기서 저자가 쓴 수법은 — 비교 · 인용 · 수치 · 사례 중" | 논문 쓰는 법 |

### 빈 답 처리 — 힌트 사다리

| 단계 | 조수가 주는 것 |
|---|---|
| 1 | 키워드 (이미 줌) |
| 2 | "O번째 문장 보세요" — 문장 위치 |
| 3 | 그 문장의 앞 절반을 읽어준다 |
| 4 | 같이 읽는다 — 조수가 그 문단을 풀어주고, 사용자가 자기 말로 다시 쓴다 |

4단계까지 가면 답은 반드시 나온다. 그 자리는 「막힌 자리」에 남기고 카드가 된다.

### 채점 — 판정 → 무엇이 틀렸나 → 근거 쪽 → 다시 쓰기

| 판정 | 조수가 하는 말 |
|---|---|
| ○ | 짧게 확인. 다음 덩어리 |
| △ | "X 는 맞고, Y 가 빠졌습니다. Y 는 N쪽 O문단 세 번째 문장." → "Y 를 넣어서 다시 써 보세요" |
| ✗ | "Z 라고 하셨는데 원문은 W 입니다 (N쪽 O문단)." → "W 를 반영해서 다시 써 보세요" |

칭찬은 짧게. 틀린 곳을 뭉개지 않는다.

## 4. 원문 텍스트 추출 — 이미지를 MD 로

스캔본이라 세션마다 이미지를 렌더링해 읽어야 했다. 한 번 옮겨 적어 두면 이후 세션은 텍스트를 읽는다.

### 위치와 형식

```
text/<슬러그>/
  p01.md          평문 — gitignore
  p01.md.enc      봉함 — 커밋
  ...
```

쪽마다 파일 하나. 머리말(front matter) + 본문.

```markdown
---
page: 3
journal_page: 41
section: "1. 서론 끝 · 2. AI 시대 개인정보 위협의 구조적 변화 · 2.1 · 2.2"
tables: ["표1 전통 vs AI 위협 모델 비교"]
figures: []
keywords: ["모델 내재화", "데이터 저장소 보호", "공격 단계", "NIST AI RMF"]
hints:
  - "2.1 은 표1 하나로 끝난다 — 행(row)이 무엇을 기준으로 나뉘는지 보세요"
  - "2.2 첫 문단에서 '7대' 를 어떤 두 축으로 분류했는지 찾으세요"
---

## 1. 서론 (이어짐)

(본문 — 문단 구분 유지)

## 2. AI 시대 개인정보 위협의 구조적 변화

### 2.1 전통 vs AI 위협 모델 비교

〈표1〉 ...
| 구분 | 전통 | AI 시대 |
|---|---|---|
| ... | ... | ... |

### 2.2 ...
```

- 제목 계층은 원문 그대로. 문단 구분 유지. 표는 md 표로. 그림은 `[그림N] 무엇을 보여주나` 한 줄
- **그림·표가 있는 쪽은 실제 페이지 이미지를 함께 둔다** — `text/<슬러그>/pages/pNN.png` (150dpi),
  md 본문 첫 줄에 `![NN쪽 원본](pages/pNN.png)`. 이미지도 `.png.enc` 로 봉해 커밋한다.
  OCR 로 뭉개지 않는다 — 옮겨 적기는 조수가 눈으로 하고, 확신 없는 글자는 `[?]` 로 표시해 재검토한다
- 각주·참고문헌 번호는 본문에 `(Carlini et al., 2021)` 식으로 그대로
- `keywords` 와 `hints` 는 튜터용이다. 원문의 문장을 옮기지 않는다 — 어디를 보라는 말만
- `journal_page = page + 38` (이 논문 기준. 논문마다 00-meta.md 의 값을 따른다)

### 누가 어떻게

- **조수가 직접 옮겨 적는다.** tesseract 가 없고, 한국어 학술문은 OCR 정확도가 떨어지며, 표·제목 계층까지 잡으려면 어차피 눈이 필요하다
- 25쪽을 병렬 에이전트 5개 (5쪽씩) 로 한 번에. 논문당 1회
- 옮긴 뒤 검수: 쪽 수 일치, 절 제목이 `00-meta.md` 쪽 색인과 맞는지, 표 개수
- 이후 세션은 `text/` 를 읽는다. 그림 · 표를 눈으로 봐야 할 때만 렌더링

### vault.py 확장

- 지금: `papers/*.pdf` 만 봉하고 연다
- 바꿈: `papers/*.pdf` + `text/*/*.md` + `text/*/pages/*.png` 를 함께. `seal` / `unseal` / `status` 셋 다
- `.md.enc` 는 `.pdf.enc` 와 같은 포맷 (`PSEAL1` + nonce + AES-GCM). 결정론적 nonce 라 다시 봉해도 diff 없음
- `status` 출력에 `text/` 항목이 쪽 단위로 25줄 나오면 시끄럽다 — 논문별로 "text 25/25 봉함" 한 줄로 묶는다

### .gitignore

```
# 원문 옮겨 적은 평문. .enc 만 올린다
text/**/*.md
```

`.md.enc` 는 `*.md` 패턴에 안 걸리므로 부정 규칙이 필요 없다.

## 5. 튜터 자기개선 — 플레이북과 로그

### `tutor/log.md` — 세션마다 조수가 적는다

```markdown
## 2026-09-03 · ai-privacy-workforce · 1차

| 시도 | 반응 (사용자 말 그대로) | 판단 |
|---|---|---|
| 1·2·17~18쪽 + 질문 3개를 한 번에 줌 | "한 번에 다 읽으라고 하면 난 못 읽어줘" | ✗ 버림 — 덩어리로 쪼갠다 |
| 1쪽 초록만 + 질문 1개 | (반응) | (판단) |
```

- 한 세션에 1~3줄. 증거는 사용자의 말을 **인용**한다 — 조수의 느낌이 아니라
- 판단은 셋 중 하나: **○ 효과** / **✗ 버림** / **? 더 볼 것**

### `tutor/playbook.md` — 검증된 것만

```markdown
# 튜터 플레이북

세션을 열 때 이 파일을 읽고 따른다. CLAUDE.md 가 뼈대라면 여기는 이 사용자에게 맞춘 살이다.

## 검증됨 (2회 이상 효과)

- ...

## 시도 중 (1회 효과, 한 번 더 보고 승격)

- ...

## 버린 것 (다시 쓰지 않는다)

- 여러 쪽 + 질문 여러 개를 한 번에 주기 — 2026-09-03, "한 번에 다 읽으라고 하면 못 읽어줘"
```

- 승격 규칙: `log.md` 에서 같은 방식이 **두 번** ○ 면 「검증됨」으로. 한 번이면 「시도 중」
- ✗ 는 즉시 「버린 것」으로. 이유와 날짜를 남긴다
- 「검증됨」이 늘면 CLAUDE.md 를 고칠 후보가 된다. 플레이북이 곧 다음 CLAUDE.md 개정의 근거
- 저장소 안에 있으므로 어느 PC 에서든 같은 튜터. 공개돼도 된다 — 논문 내용은 없고 가르치는 방법만

## 6. 기록 — 무엇을 어디에

### `notes/<슬러그>/01-sessions.md`

세션 단위 → 덩어리 단위로 바뀐다. 답은 **원문 그대로**, 1차 답과 2차 답을 다 남긴다.

```markdown
## 2026-09-03 · 1차 뼈대 · 1쪽 초록

### 덩어리 1 — 1쪽 Abstract 2문단

키워드: four-tier · Level 1~4 · Article 28 · CPO→DPO · 500억
힌트: 이 문단은 "만들겠다는 것" 과 "그걸 위해 고치겠다는 것" 두 층이다

**Q. 이 논문이 만들겠다는 게 뭔가, 한 문장으로**
> 답1: (사용자 원문)
> 피드백: △ — "4단계" 는 맞고 "누구 대상인지" 가 빠짐. 2문단 첫 문장
> 답2: (사용자 원문)
> 판정: ○ · 카드 #3

### 덩어리 2 — ...
```

「막힌 자리」 표는 유지.

### `notes/<슬러그>/04-explain.md`

「장별 내 말 요약 (통과한 것만)」 절을 추가한다. 장이 끝날 때마다 3문장이 쌓이고,
최종 5분 설명은 여기서 조립한다.

### `progress.md`

「지금 할 일」을 "N쪽 O문단부터" 로 쓴다.

### `knowledge/`

`cards.md` · `concepts.md` · `issues.md` 그대로.
카드는 (1) ✗·△ 났던 자리, (2) 왜형 질문에서 만든다. 덩어리마다가 아니라 **장마다 2~4장**.

4. `notes/<슬러그>/01-sessions.md` — 지난 답과 「막힌 자리」
5. `python scripts/vault.py status` — `text/` 평문 없으면 `unseal`
6. `text/<슬러그>/pNN.md` 이번 덩어리가 있는 쪽만 읽는다
7. 한 줄로 알린다 — "지난번 N쪽 O문단에서 멈췄고, X 가 안 잡혀 있었다. 복습 N장 먼저"
8. **첫 덩어리 하나만** 낸다 — 키워드 + 힌트 + 질문 1개. 답이 오면 다음

### 닫기 — 사용자가 말하지 않아도 조수가

1. `01-sessions.md` — 덩어리별 답1·피드백·답2·판정
2. 「막힌 자리」
3. 카드 → `review.py add` (장마다 2~4장)
4. 장이 끝났으면 `04-explain.md` 「장별 내 말 요약」
5. `tutor/log.md` — 이번 세션 1~3줄. 두 번째 ○ 면 `playbook.md` 승격
6. `knowledge/issues.md` · `concepts.md`
7. `progress.md` — "N쪽 O문단부터"
8. `python scripts/vault.py seal` 후 `git status` 로 평문 없음 확인
9. **커밋**

## 8. CLAUDE.md 개정 범위

| 절 | 무엇을 |
|---|---|
| §1 절대 규칙 | 요약 금지 → "먼저 다 풀어주지 않는다" · 통행세 → 힌트 사다리 · 한 덩어리 · 다시 쓰기 루프 · 본인 말 |
| §3 세션 여는 법 | 플레이북 읽기 · `text/` 읽기 · 첫 덩어리 하나만 |
| §4 세션 닫는 법 | `tutor/log.md` · `04-explain.md` 조립 · `seal` 확인 |
| §7 채점 | 판정 → 무엇이 틀렸나(직접) → 근거 쪽 → 다시 쓰기 |
| §8 원문 다루기 | `text/` 추출 파이프라인 · vault 가 둘 다 봉함 |
| §9 PUBLIC | `text/**/*.md` 평문 커밋 금지 · `tutor/` 는 공개 가능 |
| §10 커밋 | 타입 추가 — `text` (원문 추출 봉함) · `tutor` (플레이북 · 로그) |
| 새 절 | 덩어리 루프 · 질문 다섯 유형 · 힌트 사다리 · 플레이북 승격 규칙 |
